# 大模型协作记录与技能提炼

## 协作概述

本项目在高速采集链调试、脉冲波形分析、CNN 训练、定点实现、FPGA 接入和验证过程中使用大模型协作。

协作采用“需求与材料输入—任务拆解—工具执行—结果反馈—修正与复验”的组织方式。用户提供硬件、实测数据和波形判据，完成板级操作与测量；助手承担源码与数据分析、方案整理、脚本和逻辑修改，并调用训练、仿真与实现工具。

本文使用技能包保存的用户原话节选和工程动作摘要组织记录。详细材料见：

## 一、ADC 与 JESD204B 采集链

### 1. 从原始码开始定位

用户提示词节选：

> 不要依赖对话中ai建议，你自己独立想想问题应该在哪

> 原始 ADC 码的低 5 位固定为 0（或固定值）

模型回答与工程动作：

从解包后的原始码、配置和数据路径重建分析。统计低位集合、不同码值和相邻码值间隔，结合有效信号区分原始样点、锁存结果和独立事件。

形成的工作方法：

先量化异常，再按数据路径定位变化出现的阶段。

### 2. 按用户范围对照实际工程

用户提示词节选：

> 现在不用管v10,就看demo

> 先把fpga所以嫌疑排除，再从硬件排查

模型回答与工程动作：

按指定工程核对活动源码、ADC 配置、LMK 时钟、SPI、JESD204B 参数和运行期寄存器。将示例工程与业务工程差异逐项整理，每轮选择一个变量进行复验。

形成的工作方法：

以实际顶层和活动文件为入口，记录每项修改的输入、预期、结果和回退方式。

### 3. SPI 回读与模式核对

模型回答与工程动作：

检查 SDIO 读阶段方向、回读校验、原始串行位序和寄存器结果。结合器件资料，对照身份寄存器、工作模式及采样码行为。

针对默认寄存器核验，整理冷上电只读诊断 RTL、协议测试平台和操作说明。

## 二、脉冲 CNN 工具链与模型

### 1. 先验证转换与推理工具链

用户提示词节选：

> 我们先一步步来吗，先网上搜demo，github，先把demo跑通，再改demo，符合我们的需求

模型回答与工程动作：

采用可追溯的 hls4ml 示例模型，完成模型转换、定点 C 仿真、C/RTL 联合仿真及独立内核实现。

结果：

通用示例使用 128 组输入、640 个输出完成比较，RTL 与 C 输出逐项一致。随后将已验证的转换和校验流程用于脉冲模型。

### 2. 保留波形时间结构

用户提示词节选：

> 用现有训练模型或一个通用小网络结构，完成257点波形的软件及定点验证；核对类别、预处理和标签，不重新发明网络。

模型回答与工程动作：

比较特征型网络与小型一维 CNN，采用三层卷积、池化、全局平均和单输出结构。卷积核长度为 5、9、15，通道数为 8、8、8，训练参数为 1729 个。

通过独立前向实现检查网络结构、参数排列和计算结果，再推进定点化与硬件实现。

### 3. 统一观察窗

用户提示词节选：

> 好的，就这样做把观察窗恢复到2.56 μs，并且这段数据处理成257点，对应10 ns间隔。然后我去实测

模型回答与工程动作：

使用 1281 点、2 ns 间隔的原始帧，按中心五点整数均值和步长 5 生成 257 点输入，边缘复制端点。训练、整数参考和 RTL 使用同一预处理定义。

结果：

原始波形与 CNN 输入覆盖相同的 2.56 μs 时间范围，原始数据和模型输入分别保留。

## 三、标签、训练与定点验证

### 1. 确认逐事件规则

用户提示词节选：

> 我们人工判断氚水标准是在整个2.56us的观察窗内，大于等于4个脉冲，就认为是氚水，但是不能冲顶，冲顶就认为是宇宙射线。

关于脉冲计数的补充确认：

> 超过设定阈值就算一个，

> 只要再次过阈就算

模型回答与工程动作：

将上述判据落实为独立连续过阈区段计数：波形回落后再次过阈计为新区段；完整窗口中至少 4 个区段且未满码标为候选。

保留采集来源、触发参数和逐事件标签，按统一规则处理各来源波形。

### 2. 训练与数据划分

当前模型使用 25755 条实测波形。两个采集批次分别按时间组织训练、验证和留出集合，在相邻集合之间设置空档。

用验证集选择第 28 轮模型及工作阈值，最终默认阈值为 Q14 整数 4043，对应 0.24676513671875。

### 3. 定点与 RTL 对照

模型回答与工程动作：

将 BN 折入卷积，采用 12 位权重、8 位小数以及 24 位激活、14 位小数。建立独立整数参考，使用相同输入比较软件、HLS C 和 RTL。

结果：

- 128 组浮点对照的最大绝对误差约为 4.48×10⁻⁶。
- 两个独立整数参考在校验输入上逐分数一致。
- 128 条真实波形的 HLS C 和 RTL 得分与整数参考精确匹配。
- 3864 条时间留出波形上，浮点与定点判决一致率为 99.77%。

## 四、原始满码与事件级接入

### 1. 原始帧满码否决

开发观察：

短暂单点满码经五点均值后幅度降低，需要保留原始域判据。

模型回答与工程动作：

在均值和降采样前扫描完整 1281 点原始帧，任一点达到 65532 或以上时设置满码标志。AI 判决由得分阈值和原始满码条件联合形成，并保留判决原因。

按波形规则标签统计的时间留出结果：

| 判决 | 正类通过数 | 负类误放数 | 正类召回率 | 负类误放率 |
|---|---:|---:|---:|---:|
| 新定点 CNN | 977 | 90 | 84.15% | 3.33% |
| 新 CNN 与原始满码否决联合 | 977 | 10 | 84.15% | 0.37% |

### 2. 同一事件联合门控

模型回答与工程动作：

使用共同触发和事件号关联预筛、特征、原始缓存及 CNN 结果，锁存事件阈值，在结果就绪后统一放行或拒绝。

完成 24 帧实际 CNN 支路测试及真实顶层连接测试，检查满码、窗口首末点、背压、复位、波形上传和能谱写入之间的对应关系。

### 3. 工程运行

完成生成 RTL、权重 ROM、事件门控、综合实现和时序检查。

用户运行反馈节选：

> 不用检查了，我已经实测了，整个系统跑通了

整机测量成果、工程实现结果及对应文件分别收录于 data/、build/ 和 board/。

## 五、纠正过程

| 开发观察 | 调整内容 | 形成的方法 |
|---|---|---|
| “位数异常”表述涉及多个数据层次 | 分别统计原始码、传输格式和算法输入 | 从数据结构定位问题 |
| SPI 回读与预期不符 | 检查方向控制、校验和串行位序 | 回读值与总线行为联合核对 |
| 示例工程与业务工程表现不同 | 对照实际活动文件和运行期配置 | 单变量复验 |
| 相同点数覆盖时间不同 | 固定物理时间并统一预处理 | 采样率、窗口和点数共同管理 |
| 回摆是否计峰影响标签 | 用具体波形确认区段规则 | 标签边界显式化 |
| 原始满码经均值后降低 | 在原始帧增加独立检查 | 原始条件先于信息变换 |
| 浮点与硬件实现存在数值差异 | 建立整数参考并逐级对照 | 定点规则与测试输入版本化 |
| 单核完成后仍需连接事件链 | 检查真实顶层、缓存和最终输出 | 模块验证与事件级验证衔接 |
| 模型生成包含独立 ROM 资产 | 联合核对 RTL、权重、阈值与标识 | 模型资产成组管理 |

## 六、工作流与技能提炼

协作流程为：

需求与判据 → 原始材料分析 → 方案及工具执行 → 数值和功能比较 → 用户反馈 → 修正与复验 → 工程归档。

由此整理出：

- ADC 原始码和有效事件分析脚本。
- SPI 回读及冷上电只读诊断参考。
- 示范工程与业务工程的配置对照流程。
- 脉冲规则标签及时间划分方法。
- 浮点、整数、HLS C 和 RTL 一致性校验。
- 原始条件与模型的联合判决方法。
- 同一事件的输入、阈值、结果和缓存管理。
