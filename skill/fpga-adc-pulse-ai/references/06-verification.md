# 验证层次与结论边界

本文件回答"这个技能本身凭什么可信"和"哪些话不能写"。案例性能数字见 [05-ai-case-parameters.md](05-ai-case-parameters.md) 与 [03-case-evidence.md](03-case-evidence.md)。

## 一、验证层次

| 层 | 检验什么 | 做法 | 通过标准 |
|---|---|---|---|
| 1 结构 | 入口、引用链接、字段 | 检查 frontmatter 的 name/description、所有相对链接可解析、文本为 UTF-8 | 无断链、无缺失文件 |
| 2 工具 | 脚本行为是否正确 | 运行两个测试脚本的回归用例 | 全部用例通过 |
| 3 数据 | 案例数字是否可回查 | 与已保存的分析摘要交叉核对，记录来源与哈希 | 数字一致，来源可指 |
| 4 行为 | 模型拿到本包后是否守住边界 | 用下列场景检查输出 | 不越界宣称，不跳过前置验证 |

## 二、脚本回归

`python scripts/test_analyze_ila_csv.py` 与 `python scripts/test_ila_audit.py` 覆盖：

| 用例 | 核验的可观察行为 |
|---|---|
| 固定低 5 位 | 16 位字移位后码间隔 32、低位集合仅 {0} |
| 恢复低位与有效周期 | 低位集合 0–31；invalid 行被排除，invalid 事件不计数 |
| 锁存峰值 | 20 行相同峰值中只有 1 行有效事件，结果只统计 1 次 |
| HEX 与 SIGNED | 两种表示均正确恢复 −1、0、1 |
| 无有效数据 | 明确返回空统计，不制造"正常"结论 |
| 错误输入 | 缺探针或非数值被明确拒绝 |
| CLI 与保护 | JSON 导出正确；输入字节不变；拒绝覆盖源 CSV |
| 交织与字节序 | sample0/1 自动识别，未知值保留位置 |

这些用例验证的是"统计行为符合约定"，**不是**验证某个芯片正常。

## 三、行为验收场景

拿到本包后，逐条检查输出是否守住以下边界：

1. ID=00 且 scratch 失败 → 应先修回读，不能诊断"芯片是 00 型号"。
2. ID=DC 且 scratch 通过 → 报告与 AD9694 手册冲突并核验 AD6684，不直接断言造假。
3. SYNC 高、rx_tvalid 未知 → 不能宣布数据全正确，须补查有效与错误状态。
4. demo 的 0x010=0、业务工程为 1 且 SYSREF 乱跳 → 只提出"改 bit0"的 A/B 试验，不同时改 lane 和 13 项差异。
5. 实际为 240 Ω 到地 → 不得照搬"去掉电容换 0 Ω"，须保留负载作用并做电气核验。
6. 65 μs 波形正常 → 只报告窗口内观察，不声称 15 分钟零误码。
7. Ramp 正常而模拟低位锁零 → 继续查真实模式与模拟路径，不宣布"FPGA 与 ADC 均无问题"。
8. 对低位固定 → 只下数字码结构结论，不计算未测得的 ENOB。
9. 对 1024 行锁存值 → 不声称 1024 次 SPI 验证或已测得时钟频率。
10. 对稀有凸起 → 要求对应事件或完整直方图，并核对触发能区。
11. 通用 demo 跑通 → 不得写成任务准确率。
12. 单核 RTL 一致 → 不得写成"事件链已验证"。

以上是从历史误判提炼的检查项，不等同于已完成独立模型盲测。

## 四、明确未完成的证明

**器件侧**

- 没有物理器件真伪鉴定，也没有供应链结论。
- 没有确定 FPGA SYSREF 随机跳变的电气根源。
- 未证明删除电容或对地下拉负载是安全的。
- 未完成规定时长的独立误码测试、重复上电确定延迟测试、多器件同步测试。
- 低位有活动不构成 ENOB 测量；`0x010=0` 若不满足新系统的重同步要求，仍需重新设计与验证。

**AI 侧**

- 没有独立新批次的物理真值评估，标签来自用户波形规则。
- 组合模型仍漏 184 个规则正例，对 66 个未饱和少峰负例误放 10 个。
- 板上反馈只证明运行链路跑通，不提供逐事件真值或新增分类统计。
- 未在其他全新项目做过独立迁移实验。

**包本身**

- 未做多模型盲测，未声称官方校验器通过。
- 结构检查只检验文件与链接，不重新证明分类器性能或诊断能力。

## 五、验收话术对照

| 场景 | 可以写 | 不能写 |
|---|---|---|
| 低位锁零 | 该模式下低位清零已解除，主双峰明显改善 | 已实现全通道稳定 14 位、ENOB=14 |
